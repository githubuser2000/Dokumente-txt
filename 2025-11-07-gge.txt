1️⃣ Clipboard-Hooks grundsätzlich
Betriebssysteme haben Clipboard-APIs.

Ein „Hook“ ist ein Mechanismus, der reagiert, wenn etwas ins Clipboard geschrieben oder gelesen wird.

Man unterscheidet:

On Copy / Write: Jemand kopiert etwas → dein Hook kann Inhalt verändern.

On Paste / Read: Jemand fügt ein → dein Hook kann Inhalt verändern.

Manche Hooks sind systemweit, andere nur pro Anwendung oder per Programmierschnittstelle.

2️⃣ Betriebssystem-spezifisch
🐧 Linux
X11:

xclip/xsel können nur Inhalte setzen/lesen, kein Hook automatisch.

Für Hooks nutzt man X11-Events (SelectionNotify) in C, Python (via python-xlib) oder Qt.

Wayland:

Clipboard ist sicherer, kein globaler Hook erlaubt, nur per Wayland-Client.

Werkzeuge wie wl-clipboard können Inhalt abfragen, aber „live Hook“ ist schwieriger.

Beobachtung von Veränderungen:

Bei X11 kann man ein Programm schreiben, das auf SelectionChange Events lauscht.

Bei Wayland eher polling (wl-paste) oder mit speziellen Daemons.

🍎 macOS
Pasteboard API:

Cocoa/Objective-C/Swift erlaubt NSPasteboard Observers.

Beispiel: man registriert addObserver:forType:options:queue:usingBlock: → Callback, wenn sich Clipboard ändert.

Du siehst, wenn von außen etwas ins Clipboard geschrieben wird, indem der Observer feuert.

🪟 Windows
SetClipboardViewer / AddClipboardFormatListener:

Du kannst ein Fenster oder Programm registrieren, das Clipboard-Events empfängt.

Jedes Mal, wenn etwas ins Clipboard kommt, feuert ein Event.

GetClipboardData kann dann den Inhalt lesen und verändern.

So kann man auch erkennen, wenn ein anderer Prozess etwas kopiert hat.

3️⃣ Programmiersprachen
C / C++: System-APIs (Win32, X11, Cocoa)

Python:

Windows: pywin32 (win32clipboard) + Event Hooks

Linux: python-xlib für X11 Selection Events

macOS: pyobjc für Pasteboard Hooks

Rust / Go / Node.js:

Gibt Bibliotheken, die Clipboard überwachen, z. B. copypasta (Rust) oder clipboardy (Node), oft polling-basiert, nicht Event-basiert.

Shell/Bash:

Kein echtes Hook, nur „Push/Pull“: man kann clipboard regelmäßig lesen und ggf. ersetzen.

Windows: Man sieht nur „Clipboard hat sich geändert“, nicht welcher Prozess → man kann nachträglich auslesen, aber nicht direkt erkennen, wer geschrieben hat.

macOS: Observer feuert, aber keine direkte Quelle.

Wenn du wirklich alle Quellen tracken willst → man muss einen globalen Clipboard-Daemon bauen, der Änderungen protokolliert.

import subprocess
import time
import hashlib
from datetime import datetime

LOG_FILE = "/home/dein_user/clipboard.log"

# Intervall in Sekunden
INTERVAL = 2

def get_clipboard():
    """Liest das Wayland-Clipboard via wl-paste"""
    try:
        result = subprocess.run(["wl-paste", "-n"], capture_output=True, text=True)
        return result.stdout.strip()

        print("wl-paste nicht gefunden! Bitte installieren.")
        exit(1)

def hash_content(content):
    """Gibt einen Hash zurück, um Änderungen schnell zu erkennen"""
    return hashlib.sha256(content.encode()).hexdigest()

def log_clipboard(content):
    """Schreibt Inhalt mit Timestamp in die Log-Datei"""
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    with open(LOG_FILE, "a") as f:
        f.write(f"[{timestamp}]\n{content}\n\n")

def main():

    while True:
        content = get_clipboard()
        current_hash = hash_content(content)
        if current_hash != last_hash:
            if content:  # nur nicht-leere Inhalte loggen
                log_clipboard(content)
                print(f"Neuer Inhalt geloggt: {content[:30]}...")
            last_hash = current_hash
        time.sleep(INTERVAL)

    main()

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <openssl/sha.h>
#include <time.h>

#define LOG_FILE "/home/dein_user/clipboard.log"
#define INTERVAL 2  // Sekunden
#define MAX_LEN 65536

// Funktion zum Hashen des Inhalts
void sha256_hash(const char *str, unsigned char output[SHA256_DIGEST_LENGTH]) {
    SHA256_CTX ctx;
    SHA256_Init(&ctx);
    SHA256_Update(&ctx, str, strlen(str));
    SHA256_Final(output, &ctx);
}

// Vergleicht zwei Hashes
int hash_equal(unsigned char a[SHA256_DIGEST_LENGTH], unsigned char b[SHA256_DIGEST_LENGTH]) {
    return memcmp(a, b, SHA256_DIGEST_LENGTH) == 0;
}

// Loggt Clipboard-Inhalt mit Timestamp
void log_clipboard(const char *content) {
    FILE *f = fopen(LOG_FILE, "a");
    if (!f) return;

    time_t t = time(NULL);
    struct tm *tm_info = localtime(&t);
    char buf[64];
    strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S", tm_info);

    fprintf(f, "[%s]\n%s\n\n", buf, content);
    fclose(f);
}

int main() {
    unsigned char last_hash[SHA256_DIGEST_LENGTH] = {0};
    unsigned char current_hash[SHA256_DIGEST_LENGTH];

    while (1) {
        FILE *fp = popen("wl-paste -n 2>/dev/null", "r");
        if (!fp) {
            fprintf(stderr, "Fehler beim Ausführen von wl-paste\n");
            exit(1);
        }

        char buffer[MAX_LEN] = {0};
        fread(buffer, 1, MAX_LEN-1, fp);
        pclose(fp);

        // Entferne mögliche neue Zeilen am Ende
        buffer[strcspn(buffer, "\n")] = 0;

        if (strlen(buffer) > 0) {
            sha256_hash(buffer, current_hash);

            if (!hash_equal(current_hash, last_hash)) {
                log_clipboard(buffer);
                printf("Neuer Clipboard-Inhalt geloggt: %.30s...\n", buffer);
                memcpy(last_hash, current_hash, SHA256_DIGEST_LENGTH);
            }
        }

        sleep(INTERVAL);
    }

    return 0;
}

    const hash = hasher.final(allocator) catch return error("SHA256 failed");

}

1️⃣ !T – das „Error Union“-Typ-System
In Zig gibt es keine Exceptions wie in C++ oder Java. Stattdessen werden Fehler als Teil des Typs behandelt.

Syntax:

fn mightFail() !i32 {
    if (somethingWrong) return error.SomeError;
    return 42;
}
Erklärung:

!i32 = „Entweder ein Wert vom Typ i32 oder ein Fehler“.

Der Fehler muss behandelt werden, z.B. mit try oder catch.

const result = try mightFail(); // Wenn Fehler, stoppt das Programm hier
Vorteil:

Fehler werden explizit behandelt, kein stilles Propagieren.

Vermeidet „hidden exceptions“, wie in C++ oder Java.

Beispiel:

const std = @import("std");

fn divide(a: i32, b: i32) !i32 {
    if (b == 0) return error.DivideByZero;
    return a / b;
}

pub fn main() !void {
    const result = try divide(10, 2);
    std.debug.print("Result: {}\n", .{result});
}
Hier ist divide vom Typ !i32 – entweder ein i32 oder ein Fehler DivideByZero.

2️⃣ packed – Struktur exakt ohne Padding
In Zig (wie in C) haben structs normalerweise Padding, damit Felder richtig ausgerichtet sind.

packed erzwingt, dass die Felder ohne Padding hintereinander gespeichert werden.

    a: u8,
    b: u32,
};
Normal (ohne packed):

Offset 0: a (1 Byte)
Offset 1-3: Padding
Offset 4-7: b (4 Byte)
Total Size: 8 Bytes
Mit packed:

Offset 0: a (1 Byte)
Offset 1-4: b (4 Byte)
Total Size: 5 Bytes

Perfekt für Binärformate, Netzwerkprotokolle oder FFI mit C-Bibliotheken.
